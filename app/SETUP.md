# הקמת האפליקציה וחיבור לענן

האפליקציה שומרת הכול ב-Firebase (Firestore), ולכן **בלי חיבור היא לא עובדת**: היא מציגה מסך "לא מחוברת לענן" ולא שומרת כלום, גם לא בדפדפן. אין בה נתוני הדגמה. החיבור חינם בהיקף כזה, והאתר נשאר סטטי (GitHub Pages).

## הרצה מקומית

```bash
python -m http.server 5174
```

ואז לפתוח `http://localhost:5174/app/` (השרת רץ משורש הריפו, כדי שהלוגו מתיקיית `assets` ייטען). הכתובת המקומית עובדת מול אותו Firebase כמו האתר.

למפתחים בלבד: פתיחת `http://localhost:5174/app/?dev=1` מפעילה מנוע בדיקות מקומי (`dev/localdb.js`) בלי ענן, גם כשהקונפיגורציה מלאה, כדי לבדוק את הממשק בלי לגעת בנתונים אמיתיים. `?dev=0` מחזיר לענן. הוא לא נטען באתר המפורסם.

## חיבור ל-Firebase (פעם אחת, כ-10 דקות)

1. ב-[Firebase Console](https://console.firebase.google.com) יוצרים פרויקט חדש (בלי Google Analytics).
2. **Build ← Authentication ← Sign-in method**: מפעילים **Google** (מנהלים) ו-**Email/Password** (משתתפים נכנסים עם המייל שלהם, בלי קוד; את **Email link** משאירים כבוי). **Anonymous** כבר לא נחוץ, ואפשר להשאיר אותו פעיל בשביל משתתפים ותיקים שנכנסו בקוד. מומלץ גם: **Templates ← Password reset** לשנות שפה לעברית ושם שולח, כי משם יוצא מייל איפוס הסיסמה.
3. **Authentication ← Settings ← Authorized domains**: מוסיפים את `sashka2022.github.io` (ואת הדומיין שבו האתר יעלה).
4. **Build ← Firestore Database**: יוצרים מסד נתונים (מיקום `europe-west1` או קרוב אחר, מצב Production).
5. **Firestore ← Rules**: מדביקים את התוכן של `app/firestore.rules` ולוחצים Publish. לפני כן מוודאים שרשימת המיילים של מנהלי העל בכללים זהה ל-`SUPER_ADMINS` ב-`app/js/config.js`.
6. **Project settings ← Your apps ← Web (</>)**: רושמים אפליקציה, ומעתיקים את אובייקט ה-config אל `FIREBASE_CONFIG` ב-`app/js/config.js`. (המפתח הזה ציבורי מטבעו. האבטחה נשענת על הכללים בשלב 5.)
7. נכנסים לאפליקציה עם חשבון מנהל.ת העל, ובדף "הקבוצות שלי" מוסיפים בתחתית את המיילים של מנהלי הקבוצות.

## בדיקה אחרי החיבור

* בעמוד הפתיחה מופיעות שלוש קבוצות הערים: חיפה, בת ים ומרום הגליל. מנהל.ת העל פותח.ת אותן בלחיצה אחת בדף "הקבוצות שלי", ובדף זה יש גם כפתור "בדיקת חיבור לענן" שמוודא שהנתונים נכתבים לשרת ונקראים ממנו.
* מנהל.ת עם חשבון שאינו ברשימה מקבל.ת הודעה "החשבון הזה לא מורשה לנהל קבוצות".
* משתתף.ת בוחר.ת עיר ונכנס.ת עם מייל ושם: נפתח חשבון בלי סיסמה, והכניסה הבאה דורשת רק מייל. בכפתור "סיסמה" בכותרת אפשר להגדיר סיסמה, ואז הכניסה דורשת אותה.
* מנהל.ת בדף "משתתפים" לוחץ.ת "איפוס סיסמה": נשלח מייל שבו המשתתף.ת קובע.ת סיסמה חדשה. (איפוס שהופך חשבון חזרה ל"בלי סיסמה" דורש Cloud Functions, כלומר תוכנית Blaze, ולכן לא נעשה כרגע.)
* קבוצת הכניסה של כל עיר נקבעת ב"הגדרות הקבוצה". קבוצות ישנות מוגדרות אוטומטית כשמנהל.ת נכנס.ת לדף "הקבוצות שלי". אחרי העדכון חובה לפרסם מחדש את `firestore.rules`.
* משתתף.ת שלא פורסם לו הסילבוס רואה "הסילבוס עוד לא פורסם".
* שני משתתפים בצוות אחד: מי שפתח ראשון הוא הממלא, והשני רואה את הכתיבה בזמן אמת.

## קבצים

| קובץ | תפקיד |
|---|---|
| `index.html`, `styles.css`, `js/main.js` | מעטפת האפליקציה, ניתוב לפי hash |
| `js/views/*` | מסכים: כניסה, ניהול קבוצות, סילבוס, מסע, הובלת יוזמה, משתתפים, הגדרות |
| `js/store.js` | שכבת נתונים (Firestore) |
| `../dev/localdb.js` | מנוע בדיקות מקומי למפתחים בלבד (`?dev=1`) |
| `js/model.js` | שלבי התהליך, פורמט תאריכים |
| `initiative.html`, `js/workspace-host.js` | מרחב העבודה של הצוות (אפליקציית עץ הבעיה) והחיבור שלו לנתונים |
| `firestore.rules` | כללי אבטחה |
